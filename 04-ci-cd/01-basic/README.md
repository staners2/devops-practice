# CI/CD: базовая практика

Уровень: **базовый**. Выполняется после изучения теории по теме.

## Требуется

GitLab-проект, работающий предоставленный runner и registry; результат Docker-практики.

## Инициализация

```bash
bash artifacts/init.sh 04 01
cd 04-ci-cd/01-basic/workspace
```

Команду инициализации запускай из корня курса. Все дальнейшие команды — из рабочего каталога.

## Задание

1. Добавь .gitlab-ci.yml с этапами проверки, сборки и публикации образа.
2. В проверке валидируй конфигурацию Compose; настрой сборку образа доступным способом runner.

### Чекпоинт: проверка и сборка

- [ ] **Результат:** Runner выполняет jobs; в логах видны проверка Compose и успешная сборка моего образа.
- [ ] **Понимание:** Могу объяснить разницу pipeline, stage, job и runner. Где найду причину падения конкретной job?

3. Публикуй образ в registry с tag по commit SHA; используй переменные авторизации CI.

### Чекпоинт: образ опубликован

- [ ] **Результат:** В registry есть образ с tag commit SHA; значение секрета отсутствует в Git и показанном мной выводе.
- [ ] **Понимание:** Могу связать образ с исходным коммитом. Почему пароль registry нельзя записывать прямо в .gitlab-ci.yml?

4. Запусти pipeline по push или MR и прочитай логи каждой job.
5. Внеси ошибку в конфигурацию, зафиксируй падение проверки и исправь её.

### Чекпоинт: ошибка действительно блокирует проверку

- [ ] **Результат:** Сохранены неуспешный pipeline с намеренной ошибкой и успешный после исправления.
- [ ] **Понимание:** Могу объяснить причину отказа по журналу и показать, почему проверка не пропустила ошибку.

6. Объясни, чем публикация образа отличается от deployment и что означает rollback.

### Чекпоинт: граница поставки понятна

- [ ] **Результат:** Я показываю pipeline, его логи и опубликованный образ, не выдавая публикацию за запуск приложения.
- [ ] **Понимание:** Могу объяснить, что ещё потребуется для deployment и какой результат должен дать rollback.

## Результат

Pipeline, успешный и неуспешный запуск, опубликованный образ. Настройка собственного runner не требуется.

Сохрани свои файлы в отдельном учебном Git-репозитории. Приложи наблюдения и объяснения, а не только команды.
