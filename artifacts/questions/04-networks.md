# Блок 4. Сети

Цель блока — проверить, способен ли менти проследить путь запроса и локализовать проблему по уровню: DNS, маршрут, транспорт, TLS, HTTP или приложение.

## 1. Блок вопросов

1. Что означают IP-адрес, subnet, CIDR, gateway и route?
   **Ответ (пояснение):** IP идентифицирует интерфейс, subnet объединяет адреса одного канального сегмента, CIDR задаёт префикс сети, gateway — следующий маршрутизатор, route — правило выбора следующего перехода для сети назначения.
2. Как ОС выбирает маршрут до адреса назначения?
   **Ответ (пояснение):** ОС ищет среди подходящих маршрутов самый длинный префикс, затем учитывает метрику и политику. Для directly connected сети отправляет кадр получателю, для удалённой — следующему hop через выбранный интерфейс.
3. Чем практическая модель TCP/IP отличается от обзорной модели OSI?
   **Ответ (пояснение):** OSI делит взаимодействие на семь учебных уровней, TCP/IP группирует их в меньшее число реально используемых слоёв. Обе модели помогают локализовать сбой, но протоколы интернета не обязаны строго повторять OSI.
4. Чем TCP отличается от UDP? Что такое порт и сокет?
   **Ответ (пояснение):** TCP устанавливает соединение, обеспечивает порядок и повторную доставку; UDP отправляет независимые датаграммы без этих гарантий. Порт идентифицирует сервис на хосте, сокет — endpoint протокола с адресом и портом.
5. Как выглядит путь `домен → DNS → IP → TCP/TLS → HTTP`?
   **Ответ (пояснение):** Клиент разрешает имя в IP, выбирает маршрут, устанавливает TCP-соединение, при HTTPS согласует TLS и проверяет сертификат, затем отправляет HTTP-запрос. Ошибка каждого этапа проверяется отдельно.
6. Чем записи `A`, `AAAA`, `CNAME`, `MX` и `NS` отличаются?
   **Ответ (пояснение):** `A` указывает IPv4, `AAAA` — IPv6, `CNAME` — каноническое имя, `MX` — почтовые серверы домена с приоритетами, `NS` — авторитетные DNS-серверы зоны.
7. Что кэширует DNS и как TTL влияет на изменение записи?
   **Ответ (пояснение):** Резолверы и клиенты кэшируют положительные и отрицательные ответы. TTL задаёт допустимое время хранения, поэтому после изменения старое значение может использоваться до его истечения в каждом независимом кэше.
8. Из чего состоят HTTP request и response? Что означают классы кодов 2xx–5xx?
   **Ответ (пояснение):** Request содержит method, target, headers и иногда body; response — status, headers и body. 2xx означает успех, 3xx — перенаправление, 4xx — проблему запроса клиента, 5xx — ошибку обработки на стороне сервера.
9. Как TLS использует сертификат, CA и SNI?
   **Ответ (пояснение):** SNI сообщает серверу имя сайта до выбора сертификата. Клиент проверяет цепочку подписей до доверенного CA, срок, назначение и соответствие имени, а handshake создаёт ключи защищённого сеанса.
10. Почему CORS — не firewall и не замена авторизации?
    **Ответ (пояснение):** CORS — правило браузера для чтения cross-origin ответов JavaScript-кодом. Оно не мешает `curl`, серверным клиентам или прямому запросу, поэтому доступ защищают сетью, аутентификацией и авторизацией.
11. Чем reverse proxy отличается от load balancer?
    **Ответ (пояснение):** Reverse proxy принимает запрос от имени backend и может завершать TLS, менять заголовки и маршрутизировать. Load balancer распределяет трафик между несколькими экземплярами; один компонент часто выполняет обе роли.
12. Чем аутентификация отличается от авторизации?
    **Ответ (пояснение):** Аутентификация устанавливает, кто делает запрос. Авторизация после этого решает, какие действия и ресурсы этому субъекту разрешены; успешный вход не означает доступ ко всему.

## 2. Объяснение тем и вопросов

### Адресация и маршрутизация

CIDR задаёт длину сетевого префикса. Для `192.168.10.37/24` сеть — `192.168.10.0/24`. Если назначение находится в локальной подсети, узел отправляет кадр напрямую после ARP/NDP. Иначе выбирает маршрут с наиболее длинным совпавшим префиксом и передаёт пакет следующему hop, часто default gateway.

Модель OSI полезна как язык разделения уровней. В эксплуатации практичнее TCP/IP: link → internet/IP → transport → application. Диагностика должна идти по слоям, а не начинаться с перезапуска приложения.

### TCP, UDP и путь запроса

TCP предоставляет упорядоченный поток байтов, подтверждения, повторные передачи и контроль перегрузки. UDP отправляет датаграммы без гарантии доставки и порядка. Надёжность TCP заканчивается доставкой байтов процессу и не подтверждает обработку бизнес-операции.

Типовой HTTPS-запрос:

1. DNS возвращает адрес.
2. ОС выбирает маршрут.
3. Клиент устанавливает TCP-соединение либо QUIC поверх UDP для HTTP/3.
4. Выполняется TLS-handshake и проверка сертификата.
5. Клиент отправляет HTTP request.
6. Proxy/LB направляет его приложению.
7. Возвращается HTTP response.

### DNS

`A` указывает IPv4, `AAAA` — IPv6, `CNAME` — каноническое имя, `MX` — почтовые серверы, `NS` — авторитетные DNS-серверы зоны. Ответы могут кэшировать приложение, ОС и рекурсивный резолвер. TTL ограничивает срок использования ответа, но не гарантирует одновременное обновление всех клиентов.

### HTTP, TLS и CORS

HTTP request содержит метод, target, заголовки и иногда тело. Response содержит статус, заголовки и тело. `401` обычно связан с отсутствующей или непринятой аутентификацией, `403` — с запретом операции, `502` — с непригодным ответом upstream, `504` — с таймаутом ожидания upstream.

TLS создаёт защищённый канал и обычно подтверждает сервер через цепочку сертификатов до доверенного CA. SNI сообщает имя сервера до передачи зашифрованного HTTP-заголовка `Host`, чтобы сервер выбрал сертификат. Self-signed сертификат шифрует канал, но не доверен по умолчанию.

CORS исполняет браузер: серверными заголовками определяется, может ли JavaScript одного origin прочитать ответ другого origin. `curl` не применяет CORS. Запрос мог быть выполнен сервером, даже если браузер заблокировал чтение ответа.

### Proxy и доступ

Reverse proxy представляет backend клиенту, завершает TLS и маршрутизирует запросы. Load balancer распределяет их между экземплярами. Один компонент может выполнять обе роли. Аутентификация отвечает «кто ты?», авторизация — «что тебе разрешено?».

## 3. Вопросы для проверки знаний (с ответами)

| Вопрос | Эталонный ответ |
|---|---|
| Какой маршрут выберет ОС: `10.0.0.0/8` или `10.20.0.0/16` для `10.20.5.7`? | `/16`, потому что совпавший префикс длиннее и маршрут конкретнее. |
| Чем `connection refused` отличается от timeout? | Refused обычно означает активный отказ или отсутствие listener; timeout — отсутствие своевременного ответа из-за маршрута, firewall или недоступности. |
| Что доказывает состояние TCP `ESTABLISHED`? | Только установленное TCP-соединение; оно не доказывает успешный TLS-handshake или HTTP-ответ. |
| Чем `CNAME` отличается от HTTP redirect? | CNAME участвует в разрешении DNS; redirect — HTTP-ответ 3xx с новым адресом. |
| Почему TTL уменьшают до миграции DNS? | Уже закэшированные записи сохраняют старый TTL; предварительное уменьшение сокращает окно использования старого значения после переключения. |
| Почему `curl` получает 200, а браузер показывает CORS error? | Сервер ответил, но браузер не разрешил JavaScript прочитать ответ либо не прошёл preflight. |
| Зачем SNI, если есть заголовок `Host`? | Сертификат выбирают во время TLS-handshake, до чтения зашифрованного HTTP-заголовка. |
| Чем 502 отличается от 504? | 502 — proxy получил некорректный/непригодный ответ; 504 — не дождался ответа вовремя. |
| Валидный сертификат доказывает безопасность приложения? | Нет. Он защищает канал и подтверждает имя в рамках доверия, но не исключает уязвимости приложения. |
| Какие уровни проверяет `curl -v`? | DNS-результат, подключение, proxy, TLS, отправленные и полученные HTTP-заголовки; он не показывает весь маршрут и может раскрыть секреты в выводе. |

Практика: попросите объяснить, чего не доказывает успех каждой команды: `dig`, `nc -vz host 443`, `openssl s_client`, `curl -v`.
