# Блок 2. Bash и Python

Цель блока — проверить способность писать предсказуемую автоматизацию, корректно обрабатывать ошибки и не раскрывать секреты.

## 1. Блок вопросов

1. Что делает shebang `#!/usr/bin/env bash`?

   **Ответ (пояснение):** При прямом запуске файла ядро использует shebang для выбора интерпретатора. Вариант с `/usr/bin/env` ищет `bash` через текущий `PATH`; при запуске `bash script.sh` shebang не выбирает интерпретатор.

2. Зачем заключать переменные в кавычки? Чем `$@` отличается от `"$@"`?

   **Ответ (пояснение):** Кавычки предотвращают разбиение значения по пробелам и раскрытие glob-шаблонов. `"$@"` передаёт каждый исходный аргумент отдельным аргументом, тогда как некавыченный `$@` может изменить их границы.

3. Как Bash использует exit codes в `if`, `&&` и `||`?

   **Ответ (пояснение):** Код `0` означает успех, ненулевой — ошибку или отрицательный результат. `if` проверяет код команды, `A && B` запускает B после успеха A, `A || B` — после неуспеха A.

4. Когда применять `case`, цикл и функцию?

   **Ответ (пояснение):** `case` подходит для выбора ветки по шаблону, цикл — для повторения над набором или условием, функция — для именованного повторно используемого действия с понятным контрактом и кодом возврата.

5. Чем пайп отличается от перенаправления?

   **Ответ (пояснение):** Пайп `A | B` соединяет stdout процесса A со stdin процесса B. Перенаправление связывает дескриптор команды с файлом или другим дескриптором и не обязательно создаёт цепочку процессов.

6. Для чего нужны `grep`, `find`, `xargs` и `jq`?

   **Ответ (пояснение):** `grep` фильтрует текст, `find` ищет объекты файловой системы, `xargs` строит аргументы команд из входного потока, `jq` структурно читает и преобразует JSON. Для имён с пробелами используют нулевые разделители `-print0` и `-0`.

7. Что меняет `set -euo pipefail` и почему он не заменяет обработку ошибок?

   **Ответ (пояснение):** `-e` завершает shell при части необработанных ошибок, `-u` запрещает неопределённые переменные, `pipefail` возвращает ошибку любого элемента пайпа. У этих режимов есть контекстные исключения, поэтому ожидаемые ошибки всё равно обрабатывают явно.

8. Почему `bash -x` опасно включать в CI без проверки?

   **Ответ (пояснение):** Трассировка печатает раскрытые команды и значения переменных, поэтому токены, пароли и ключи могут попасть в job log. Отладку ограничивают, секреты не передают командной строкой и отключают `set -x` вокруг чувствительных операций.

9. Зачем Python-проекту `venv` и файл зависимостей?

   **Ответ (пояснение):** `venv` изолирует установленные пакеты от системного Python и других проектов. Файл зависимостей фиксирует воспроизводимый набор библиотек, а lockfile или точные версии уменьшают расхождения между средами.

10. Как безопасно читать переменные окружения и выполнять HTTP-запросы?

    **Ответ (пояснение):** Обязательные переменные проверяют при старте и не выводят их значения в лог. HTTP-запросам задают timeout, проверяют статус, ограничивают повторные попытки и отдельно обрабатывают сетевые, HTTP- и ошибки формата ответа.

11. Как различать сетевую ошибку, HTTP 500 и невалидный JSON?

    **Ответ (пояснение):** Сетевая ошибка возникает до корректного HTTP-ответа; HTTP 500 — валидный ответ сервера со статусом ошибки; невалидный JSON обнаруживается при разборе тела. Эти этапы должны иметь разные исключения и сообщения диагностики.

12. Зачем автоматизации logging и предсказуемые коды завершения?

    **Ответ (пояснение):** Структурные логи объясняют этап, объект и причину сбоя, не раскрывая секреты. Код `0` сообщает оркестратору об успехе, ненулевой код позволяет CI, cron или systemd корректно отметить и обработать ошибку.

## 2. Объяснение тем и вопросов

### Bash minimum

Shebang используется при прямом запуске исполняемого файла. `#!/usr/bin/env bash` ищет Bash через `PATH`; при `bash script.sh` интерпретатор уже выбран командой запуска.

Переменная задаётся без пробелов: `name=value`. Двойные кавычки разрешают подстановки, но сохраняют результат одним аргументом. `"$@"` передаёт все аргументы, сохраняя их границы. Без кавычек пробелы и wildcard могут неожиданно разбить или расширить значение.

Код `0` означает успех, ненулевой — ошибку или специальный результат. Условия Bash обычно проверяют код команды:

```bash
if curl --fail --silent --show-error "$url"; then
  echo "service is available"
else
  echo "service check failed" >&2
  exit 1
fi
```

`set -u` запрещает неинициализированные переменные, `pipefail` учитывает ошибку любой команды пайпа, `-e` завершает скрипт при ряде необработанных ошибок. У `-e` есть исключения, поэтому ожидаемые ошибки всё равно обрабатывают явно.

`find ... -print0 | xargs -0 ...` безопасно сохраняет имена с пробелами. `jq` предназначен для структурной обработки JSON; `grep` не должен подменять JSON-парсер.

### Python minimum

`venv` изолирует зависимости. Команда `python -m pip` однозначно использует pip выбранного интерпретатора. `requirements.txt` фиксирует устанавливаемый набор, а `uv` может управлять окружением, зависимостями и lock-файлом как единым workflow.

Обязательную настройку читают так, чтобы отсутствие было явной ошибкой. HTTP-запросу задают timeout, вызывают `raise_for_status()` и отдельно обрабатывают ошибки транспорта и формата ответа.

```python
import logging
import os
import sys

import requests


def main() -> int:
    url = os.environ.get("SERVICE_URL")
    if not url:
        logging.error("SERVICE_URL is required")
        return 2

    try:
        response = requests.get(url, timeout=5)
        response.raise_for_status()
        payload = response.json()
    except (requests.RequestException, ValueError) as error:
        logging.error("Service check failed: %s", error)
        return 1

    return 0 if payload.get("status") == "ok" else 1


if __name__ == "__main__":
    sys.exit(main())
```

Нельзя записывать в лог токены, пароли и полные заголовки авторизации. Exit code должен позволять CI, cron или monitoring отличить успех от ошибки конфигурации и ошибки выполнения.

## 3. Вопросы для проверки знаний (с ответами)

| Вопрос | Эталонный ответ |
|---|---|
| Почему опасна команда `rm -rf $directory/*`? | Пустое значение, пробелы и globbing могут изменить набор аргументов. Нужны кавычки, валидация непустого допустимого пути и защитные ограничения. |
| Чем `return 1` отличается от `exit 1` в функции Bash? | `return` завершает функцию с кодом, `exit` завершает весь shell-скрипт. |
| Почему ошибка первой команды пайпа может потеряться? | Без `pipefail` код пайпа обычно равен коду последней команды. |
| Чем `>` отличается от `>>`? | `>` создаёт или перезаписывает файл, `>>` дописывает в конец. |
| Почему `bash -x` может раскрыть секрет? | Трассировка печатает команды после подстановки переменных, включая токены и пароли. |
| Почему `python -m pip` надёжнее `pip`? | Он связывает установщик с конкретным выбранным интерпретатором Python. |
| Почему `requests.get(url)` без timeout опасен? | Скрипт может ждать неопределённо долго и заблокировать job или проверку. |
| HTTP 500 автоматически вызывает исключение в `requests`? | Нет. Для статусов 4xx/5xx нужно вызвать `raise_for_status()` или проверить `status_code`. |
| Что произойдёт, если сервер вернёт HTML вместо JSON? | `response.json()` завершится ошибкой декодирования; её нужно обработать отдельно от HTTP-статуса. |
| Когда использовать `os.environ[...]`, а когда `os.getenv()`? | Первый вариант удобен для обязательной настройки и явно падает при отсутствии; второй — когда допустим `None` или осмысленное значение по умолчанию. |

Практика: попросите написать Bash-скрипт поиска ошибок в логах и Python-скрипт проверки HTTP-сервиса. Оценивайте кавычки, timeout, stderr, отсутствие секретов в логах и разные exit codes.
