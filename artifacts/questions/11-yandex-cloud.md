# Блок 11. Yandex Cloud

Цель блока — проверить понимание базовых облачных сущностей, IAM, сети, вычислений, object storage, registry, стоимости и безопасной автоматизации.

## 1. Блок вопросов

1. Чем cloud отличается от folder и availability zone?
   **Ответ (пояснение):** Cloud — верхний контейнер ресурсов и политик организации, folder — более узкая административная и биллинговая группа внутри cloud, availability zone — физически отделённая площадка региона для размещения ресурсов.
2. Что такое service account и зачем он автоматизации?
   **Ответ (пояснение):** Service account — непривязанная к человеку identity для workload или CI. Ему назначают минимальные роли, используют короткоживущие credentials и могут независимо отозвать доступ без личной учётной записи инженера.
3. Как работают IAM roles и принцип наименьших привилегий?
   **Ответ (пояснение):** Role объединяет разрешения, binding выдаёт её субъекту на конкретном resource scope. Наименьшие привилегии означают только необходимые действия, только на нужные ресурсы и по возможности на ограниченное время.
4. Почему личный admin-доступ не следует использовать в CI/CD?
   **Ответ (пояснение):** Он даёт pipeline избыточные права, плохо отделяется от человека и усложняет аудит и отзыв. CI должен использовать отдельный service account с ограниченной ролью и управляемым секретом или federation.
5. Чем VPC network отличается от subnet?
   **Ответ (пояснение):** VPC network является логическим сетевым пространством, subnet выделяет конкретный CIDR в availability zone. Ресурс подключается к subnet и получает адрес, а маршруты и security groups управляют доступностью.
6. Чем public IP отличается от private IP?
   **Ответ (пояснение):** Private IP маршрутизируется внутри облачной сети и связанных приватных сетей. Public IP доступен через интернет-маршрутизацию или NAT; его наличие не отменяет firewall и security-group правила.
7. Что контролирует security group и чем она отличается от firewall внутри VM?
   **Ответ (пояснение):** Security group фильтрует трафик интерфейса на уровне облачной платформы по направлениям, протоколам, портам и источникам. Host firewall работает внутри ОС; слои дополняют друг друга и диагностируются отдельно.
8. Что такое Compute Cloud VM, SSH-доступ и cloud-init?
   **Ответ (пояснение):** VM — виртуальная машина с image, CPU, RAM, disks и network interfaces. SSH даёт защищённый shell по ключу, cloud-init выполняет первичную декларативную настройку при создании экземпляра.
9. Что такое Object Storage и S3-compatible API?
   **Ответ (пояснение):** Object Storage хранит объекты в buckets с ключами и метаданными, а не обычную POSIX-файловую систему. S3-compatible API позволяет использовать распространённые клиенты, подписи и операции загрузки, чтения и lifecycle.
10. Для чего нужен Container Registry?
    **Ответ (пояснение):** Registry хранит версии container images и предоставляет push/pull API, контроль доступа и иногда сканирование. Workload должен ссылаться на определённый tag или, для неизменяемой поставки, digest.
11. Что дают managed PostgreSQL, Kubernetes и Kafka?
    **Ответ (пояснение):** Провайдер берёт на себя часть жизненного цикла платформы: развертывание, обновления, резервирование и мониторинг по заявленному SLA. Клиент всё равно отвечает за схему, данные, доступы, capacity и корректность приложения.
12. Как ограничивать расходы и что нужно удалить после практики?
    **Ответ (пояснение):** Заранее задают budgets/alerts, выбирают минимальные размеры и отслеживают дорогие ресурсы. После практики удаляют VM, disks и snapshots, public IP, load balancers, managed clusters/databases, registries и временные service accounts, проверяя итоговый биллинг.

## 2. Объяснение тем и вопросов

Cloud — верхнеуровневая область ресурсов и доступа. Folder группирует ресурсы, IAM и billing-контекст внутри cloud. Availability zone — физически обособленная зона размещения; распределение по зонам повышает устойчивость только вместе с архитектурой приложения и данных.

### IAM

Service account — машинная идентичность для VM, приложения или pipeline. Роль выдаётся на конкретный scope: resource, folder или cloud. Чем выше scope и шире роль, тем больше blast radius. В автоматизации применяют отдельный service account с минимальными permissions и короткоживущими credentials, когда сервис это поддерживает.

Статический ключ нужно хранить в secret manager/CI variable, ограничивать и ротировать. Личный admin связывает automation с сотрудником, усложняет аудит и выдаёт лишние права.

### Сеть и Compute

VPC network объединяет subnets; subnet имеет CIDR и привязана к зоне. Private IP используется внутри маршрутизируемой сети, public IP обеспечивает внешний маршрут при разрешающих правилах. Security group фильтрует трафик на облачном уровне, host firewall — внутри ОС. Для доступности должны разрешать оба слоя и маршрутизация.

Cloud-init выполняет начальную конфигурацию VM: пользователь, SSH-ключи, пакеты и файлы. Он не заменяет полноценное долгосрочное configuration management и требует защиты передаваемых секретов.

### Storage, Registry и managed services

Object Storage хранит объекты в buckets через S3-compatible API. Он подходит для артефактов, backup-файлов и статики, но не является обычной POSIX-файловой системой. Доступ, versioning, lifecycle и публичность настраиваются отдельно.

Container Registry хранит images по repository/tag/digest. Managed services снимают часть задач установки, патчей и infrastructure failover, но ответственность за схему, запросы, доступ, backup policy, capacity и стоимость остаётся у пользователя.

### Стоимость и безопасность

Перед практикой задают бюджет/уведомления, labels и список ресурсов. После — удаляют VM, диски, snapshots, public IP, load balancers и другие тарифицируемые объекты. Остановка VM не всегда прекращает оплату дисков и адресов.

## 3. Вопросы для проверки знаний (с ответами)

| Вопрос | Эталонный ответ |
|---|---|
| Зачем CI отдельный service account? | Для независимой машинной идентичности, минимальных прав, аудита и простой ротации без личного аккаунта. |
| Роль на cloud и folder эквивалентны? | Нет. Cloud-level охватывает более широкий scope; предпочтителен минимально необходимый уровень. |
| Security group разрешает 443, но сервис недоступен. Что ещё проверить? | Route/public IP, host firewall, listener, health приложения, DNS и TLS. |
| Public IP делает VM безопасно доступной? | Нет. Он создаёт адресуемость; безопасность определяют правила, сервисы, патчи, аутентификация и журналирование. |
| Почему Object Storage называют S3-compatible? | Он предоставляет API, совместимый с распространённой моделью S3, но конкретные возможности нужно сверять с документацией провайдера. |
| Подходит ли bucket как обычный диск PostgreSQL? | Нет. Object storage не даёт обычную локальную файловую семантику и latency, ожидаемые БД. |
| Зачем Registry хранить digest вместе с tag? | Tag может перемещаться, digest однозначно фиксирует содержимое image. |
| Managed PostgreSQL снимает всю ответственность с команды? | Нет. Провайдер управляет платформой, но команда отвечает за доступ, данные, схему, запросы, backup requirements и стоимость. |
| Почему выключить VM недостаточно для остановки расходов? | Диски, snapshots, IP и другие ресурсы могут продолжить тарифицироваться. |
| Что проверить перед удалением учебного folder? | Нужные данные/backup, зависимости, список ресурсов и отсутствие shared production-объектов. |

Практика: попросите спроектировать доступ CI к Container Registry без личного admin и назвать scope роли, способ хранения credentials и порядок ротации.
