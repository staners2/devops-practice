# Linux и сети: базовая практика

Уровень: **02 — углубление параллельно собеседованиям**. Выполняй после теории этой темы. Первая неделя не требует этой практики.

## Требуется

Учебная Ubuntu VM, SSH и sudo.

## Инициализация

```bash
bash 02-interviews-and-practice/artifacts/init.sh 02 01 01
cd 02-interviews-and-practice/01-linux-networks/01-basic/workspace
```

Команду инициализации запускай из корня курса. Все дальнейшие команды — из рабочего каталога.

## Задание

1. Подключись по SSH и определи ОС, пользователя, текущий каталог и свободное место.
2. Создай каталог и файл; измени права и объясни доступ владельца, группы и остальных.

### Чекпоинт: ориентация и права

- [ ] **Результат:** Я показываю текущий каталог, владельца и права созданного файла; изменение прав даёт ожидаемый доступ.
- [ ] **Понимание:** Могу объяснить абсолютный и относительный путь и права owner/group/other. Как проверю, от какого пользователя выполняется команда?

3. Установи nginx, включи автозапуск и проверь состояние через systemctl.
4. Найди процесс, слушающий порт, через ss; проверь HTTP-ответ через curl.

### Чекпоинт: сервис доступен

- [ ] **Результат:** nginx запущен, нужный порт слушается, curl получает HTTP-ответ; я сохранил вывод этих проверок.
- [ ] **Понимание:** Могу различить состояние процесса, наличие порта и ответ приложения. Доказывает ли один LISTEN исправность сайта?

5. Посмотри IP, маршрут по умолчанию и результат DNS-запроса. Объясни путь запроса от имени до процесса.
6. Останови только учебный nginx, зафиксируй симптом и восстанови его. Найди записи в journalctl.

### Чекпоинт: причина недоступности найдена

- [ ] **Результат:** Есть IP, маршрут и DNS-ответ; после остановки nginx я зафиксировал ошибку, восстановил HTTP и нашёл записи в журнале.
- [ ] **Понимание:** Могу по результатам проверок отличить проблему DNS, соединения и сервиса. Чем запуск сейчас отличается от автозапуска?

## Результат

Команды, HTTP-ответ, статус сервиса, объяснение прав и причины неисправности.

Сохрани свои файлы в отдельном учебном Git-репозитории. Приложи наблюдения и объяснения, а не только команды.
