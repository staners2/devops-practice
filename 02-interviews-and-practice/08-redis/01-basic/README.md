# Redis: базовая практика

Уровень: **02 — углубление параллельно собеседованиям**. Выполняй после теории этой темы. Первая неделя не требует этой практики.

## Требуется

Docker и redis-cli (можно внутри контейнера).

## Инициализация

```bash
bash 02-interviews-and-practice/artifacts/init.sh 02 08 01
cd 02-interviews-and-practice/08-redis/01-basic/workspace
```

Команду инициализации запускай из корня курса. Все дальнейшие команды — из рабочего каталога.

## Задание

1. Запусти Redis в отдельном учебном контейнере и сохрани использованную конфигурацию.
2. Запиши и прочитай значение через SET/GET; проверь EXISTS и DEL.

### Чекпоинт: ключи управляются

- [ ] **Результат:** SET/GET показывают ожидаемое значение, EXISTS и DEL подтверждают наличие и удаление выбранного ключа.
- [ ] **Понимание:** Могу объяснить, что возвращает чтение отсутствующего ключа и как это влияет на использование кеша.

3. Задай EXPIRE, посмотри TTL и проверь исчезновение ключа.

### Чекпоинт: TTL наблюдается

- [ ] **Результат:** Я сохранил TTL до истечения и факт исчезновения ключа после него.
- [ ] **Понимание:** Могу объяснить назначение срока жизни и отличить истёкший ключ от ошибки соединения.

4. Создай счётчик через INCR и объясни применение.

### Чекпоинт: счётчик изменяется

- [ ] **Результат:** Последовательные INCR дают ожидаемые значения контрольного счётчика.
- [ ] **Понимание:** Могу объяснить, для какой задачи нужен счётчик и чем это отличается от хранения обычной строки.

5. Перезапусти контейнер и проверь данные; объясни результат с учётом volume, RDB и AOF.

### Чекпоинт: перезапуск объяснён

- [ ] **Результат:** Зафиксированы настройки хранения, наличие volume и результат чтения контрольного ключа после перезапуска.
- [ ] **Понимание:** Могу объяснить сохранение или потерю значения с учётом RDB/AOF и конфигурации; не считаю volume гарантией сохранения всех записей.

## Результат

Команды, наблюдения TTL и объяснение результата перезапуска. Не используй рабочий Redis.

Сохрани свои файлы в отдельном учебном Git-репозитории. Приложи наблюдения и объяснения, а не только команды.
