# Kafka: базовая практика

Уровень: **02 — углубление параллельно собеседованиям**. Выполняй после теории этой темы. Первая неделя не требует этой практики.

## Требуется

Docker Compose; стенд deploy/kafka-lab копируется при инициализации.

## Инициализация

```bash
bash 02-interviews-and-practice/artifacts/init.sh 02 09 01
cd 02-interviews-and-practice/09-kafka/01-basic/workspace
```

Команду инициализации запускай из корня курса. Все дальнейшие команды — из рабочего каталога.

## Задание

1. Запусти предоставленный Kafka Compose как отдельный учебный project.
2. Создай topic и отправь несколько сообщений через Kafka CLI в контейнере.

### Чекпоинт: сообщение записано

- [ ] **Результат:** Учебный topic существует; producer завершил отправку контрольных сообщений без ошибки.
- [ ] **Понимание:** Могу объяснить роли broker, topic, partition и producer. Доказывает ли успех отправки обработку consumer’ом?

3. Прочитай сообщения одной consumer group и повтори чтение другой группой.

### Чекпоинт: чтение группами проверено

- [ ] **Результат:** Контрольные сообщения прочитаны; я показываю результаты чтения одной и другой consumer group.
- [ ] **Понимание:** Могу объяснить, почему независимая группа может прочитать те же события, а чтение не удаляет их из topic.

4. Покажи offsets и lag через consumer-groups CLI.

### Чекпоинт: позиция обработки измерена

- [ ] **Результат:** Я показываю offsets и lag своей группы и соотношу их с отправленными сообщениями.
- [ ] **Понимание:** Могу объяснить, что измеряет lag и почему нулевой lag сам по себе не доказывает успех бизнес-операции.

5. Объясни, почему прочтение не удаляет сообщение и что ограничивает retention.

### Чекпоинт: хранение отделено от чтения

- [ ] **Результат:** По настройкам выданного стенда я показываю, как ограничено хранение сообщений.
- [ ] **Понимание:** Могу объяснить, чем retention отличается от commit offset и почему обработчик должен учитывать повторные события.

## Результат

Команды producer/consumer, вывод групп и объяснение partition, offset и lag. Не требуется сложный consumer-код.

Сохрани свои файлы в отдельном учебном Git-репозитории. Приложи наблюдения и объяснения, а не только команды.
