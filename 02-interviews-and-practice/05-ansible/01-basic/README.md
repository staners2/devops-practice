# Ansible: базовая практика

Уровень: **02 — углубление параллельно собеседованиям**. Выполняй после теории этой темы. Первая неделя не требует этой практики.

## Требуется

Ansible на control node, учебная Ubuntu VM с SSH и sudo.

## Инициализация

```bash
bash 02-interviews-and-practice/artifacts/init.sh 02 05 01
cd 02-interviews-and-practice/05-ansible/01-basic/workspace
```

Команду инициализации запускай из корня курса. Все дальнейшие команды — из рабочего каталога.

## Задание

1. Создай inventory с учебным сервером и проверь подключение модулем ping.

### Чекпоинт: доступ к узлу

- [ ] **Результат:** Inventory выбирает нужный учебный сервер; модуль ping завершается успешно.
- [ ] **Понимание:** Могу объяснить, что проверяет Ansible ping и чем он отличается от сетевого ICMP ping.

2. Напиши playbook установки nginx, размещения страницы и включения сервиса.
3. Используй become для административных задач и переменную для текста страницы.
4. Проверь синтаксис, запусти playbook и проверь страницу через curl.

### Чекпоинт: первое применение

- [ ] **Результат:** Playbook проходит проверку синтаксиса, устанавливает nginx, размещает страницу; curl получает ожидаемый текст.
- [ ] **Понимание:** Могу показать задачи установки, настройки и запуска и объяснить, зачем им become.

5. Повтори запуск и объясни changed и идемпотентность.

### Чекпоинт: повторное применение

- [ ] **Результат:** Повторный запуск не меняет уже достигнутое состояние; я могу объяснить каждый оставшийся changed, если он есть.
- [ ] **Понимание:** Могу объяснить идемпотентность и отличить реальное изменение от задачи, которая сообщает changed каждый раз.

6. Добавь template конфигурации, её проверку nginx -t до активации и reload через handler.

### Чекпоинт: конфигурация применяется намеренно

- [ ] **Результат:** Изменение переменной меняет template; перед активацией проходит nginx -t, затем handler применяет изменение.
- [ ] **Понимание:** Могу объяснить отличие copy от template, условия вызова handler и ограничения --check.

## Результат

Inventory, playbook, template и результат двух запусков. Объясни назначение roles; писать сложные roles не требуется.

Сохрани свои файлы в отдельном учебном Git-репозитории. Приложи наблюдения и объяснения, а не только команды.
