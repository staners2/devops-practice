# Kubernetes: базовая практика

Уровень: **02 — углубление параллельно собеседованиям**. Выполняй после теории этой темы. Первая неделя не требует этой практики.

## Требуется

Готовый учебный кластер, kubectl, Helm и предоставленный StorageClass.

## Инициализация

```bash
bash 02-interviews-and-practice/artifacts/init.sh 02 06 01
cd 02-interviews-and-practice/06-kubernetes/01-basic/workspace
```

Команду инициализации запускай из корня курса. Все дальнейшие команды — из рабочего каталога.

## Задание

1. Создай namespace и Deployment nginx с двумя репликами; сопоставь Pod, ReplicaSet и Deployment.

### Чекпоинт: контроллер поддерживает Pod’ы

- [ ] **Результат:** Deployment имеет две готовые реплики; я нахожу связанные ReplicaSet и Pod’ы.
- [ ] **Понимание:** Могу объяснить, зачем нужен Deployment и почему его Pod после удаления появляется снова.

2. Создай ClusterIP Service и проверь доступ через port-forward; проверь labels и selector.

### Чекпоинт: доступ к приложению

- [ ] **Результат:** Selector Service соответствует labels; через port-forward получен HTTP-ответ.
- [ ] **Понимание:** Могу показать соответствие Service и Pod’ов. Почему port-forward сам по себе не доказывает доступность сервиса из внешней сети?

3. Подключи ConfigMap и Secret, задай requests/limits и readiness/liveness probes.

### Чекпоинт: конфигурация и проверки

- [ ] **Результат:** Pod использует мою конфигурацию, у контейнера заданы ресурсы и probes; значения Secret не попали в отчёт.
- [ ] **Понимание:** Могу объяснить requests/limits и readiness/liveness. Почему Running не равен Ready?

4. Обнови image, проверь rollout и выполни rollback.

### Чекпоинт: обновление и откат

- [ ] **Результат:** Зафиксированы image до обновления, результат rollout и фактический image после rollback.
- [ ] **Понимание:** Могу объяснить, какую версию вернул откат и как убедиться, что приложение снова готово.

5. Подключи PVC и проверь сохранность учебного файла после пересоздания Pod.

### Чекпоинт: данные вне Pod

- [ ] **Результат:** PVC привязан, файл записан на том и сохранился после пересоздания Pod с тем же PVC.
- [ ] **Понимание:** Могу связать Pod, PVC, PV и StorageClass. Доказывает ли этот опыт сохранность данных при отказе узла?

6. По очереди воспроизведи неверный image tag, ошибочный selector и остановку процесса. Найди причины через get, describe, events и logs.

### Чекпоинт: типовые ошибки найдены

- [ ] **Результат:** Для неверного image, selector и падения процесса сохранены симптом, диагностический вывод и проверка после исправления.
- [ ] **Понимание:** Могу выбрать get, describe, events или logs по симптому и объяснить найденную причину.

7. Установи небольшой предоставленный Helm chart, изменив один параметр values.

### Чекпоинт: Helm values работают

- [ ] **Результат:** Готовый chart установлен; изменённый параметр values виден в фактической конфигурации release.
- [ ] **Понимание:** Могу объяснить разницу chart, release и values и проверить результат изменения.

## Результат

Манифесты, результаты rollout, storage-проверки и объяснение трёх неисправностей. Установка кластера не требуется.

Сохрани свои файлы в отдельном учебном Git-репозитории. Приложи наблюдения и объяснения, а не только команды.
