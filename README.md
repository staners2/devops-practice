# Практический курс DevOps

Этот репозиторий содержит задания курса, стартовое приложение и файлы учебных стендов.
В ходе курса ты запускаешь готовое приложение, организуешь его поставку,
переносишь в Kubernetes, настраиваешь наблюдаемость и отрабатываешь
эксплуатацию инфраструктуры. Условия всех заданий доступны из этого README.

## Перед началом

Повтори основы Linux, командной строки и Bash, Git, TCP/IP, DNS, HTTP и Docker.
Материалы по темам находятся в [questions/](artifacts/questions/).
Программировать приложение с нуля не требуется. Исходное приложение находится
в [практике 00](tasks/00/README.md); создай рабочую копию командой инициализации.
Все задания и файлы стендов доступны после одного клонирования репозитория.
Для доступа к модулям не нужно переключать ветки, теги или открывать worktree.

Каталог `artifacts/common`
содержат накопленные реализации и материалы стендов. Готовые реализации служат
примерами; собственные pipeline, charts, inventory и инфраструктуру создавай
в своём учебном проекте по условиям заданий. Для последовательного маршрута
используй свой результат предыдущего модуля. Для самостоятельного старта
используй предоставленные файлы корня курса и требования выбранного модуля.
Команды и пути в модулях 01–08 относятся к корню соответствующего учебного
проекта; команды модуля 00 запускай из `tasks/00/workspace`.

## Что требуется

- Компьютер с 16 ГБ RAM для полного локального маршрута. Не держи все стенды
  запущенными одновременно; ограничения конкретного модуля указаны в задании.
- Git, терминал, Docker Desktop либо Docker Engine с Compose и GNU Make
  для стартового приложения. Дополнительные инструменты и закреплённые версии
  устанавливай по инструкциям выбранного модуля.
- Доступ к интернету для получения образов, пакетов и работы с GitLab.
- Аккаунт GitLab.com, учебный проект и собственный runner для CI/CD-модулей;
  Telegram-бот и чат для задания с уведомлениями.
- Для Ansible — гипервизор и две учебные Ubuntu VM, SSH и control node.
- Для Terraform — аккаунт Yandex Cloud с платёжными реквизитами, правами
  создания учебных ресурсов и согласованным бюджетом.
- Для Linux-инцидентов — отдельная Ubuntu Server 24.04 LTS VM со snapshot.

На Windows используй окружение, указанное в инструкции модуля: для Kafka
подходит Git Bash с Docker Desktop в режиме Linux containers, для остальных
инструментов проверь требования в runbook. Поддержка ОС и архитектуры зависит
от выбранного стенда.

## В какой последовательности проходить

Основной маршрут — 00 → 01 → 02 → дополнительная практика Kubernetes → 03 →
04 → 05 → 06 → 07 → 08 → 09.

| Этап | Задание | Что отрабатываешь |
| --- | --- | --- |
| 00 | [Стартовое приложение](tasks/00/README.md) | Локальный запуск и проверка потока данных |
| 01 | [GitLab CI/CD](tasks/01/README.md) | GitLab Flow, runner, проверки, сборка и публикация образа |
| 02 | [Kubernetes и Helm](tasks/02/README.md) | Кластер, Helm chart, probes и поставка приложения |
| После 02 | [Дополнительная практика Kubernetes](tasks/02-extra/README.md) | CNI, MetalLB, хранилища, RBAC, NetworkPolicy и DaemonSet |
| 03 | [GitOps с Argo CD](tasks/03/README.md) | Desired state в Git, синхронизация и проверка развёртывания |
| 04 | [Наблюдаемость](tasks/04/README.md) | Метрики, логи, алерты и диагностика |
| 05 | [PostgreSQL и Patroni](tasks/05/README.md) | Backup/restore, SQL-диагностика и отказоустойчивость |
| 06 | [Kafka](tasks/06/README.md) | Topics, consumer groups, offsets, lag и хранение событий |
| 07 | [Ansible](tasks/07/README.md) | Управление двумя VM, идемпотентность, обновление и rollback |
| 08 | [Terraform и Yandex Cloud](tasks/08/README.md) | Облачная инфраструктура, state и сетевые ограничения |

При последовательном прохождении используй результат предыдущего этапа,
если это предусмотрено условием. Kafka, Ansible, Terraform и Linux-инциденты
допускают отдельный маршрут с собственной подготовкой. Для остальных модулей
возможность независимого старта и необходимые исходные материалы проверяй
в задании.

## Как выполнять каждый модуль

1. Прочитай условие целиком: цель, исходное состояние, ограничения и результаты.
2. Повтори соответствующую теорию в [questions/](artifacts/questions/).
3. Подготовь среду по инструкции модуля и связанным
   [runbooks](artifacts/common/docs/runbooks/).
4. Выполни задание в своём учебном проекте. Сохраняй конфигурации и автоматизацию
   в Git; секреты и ключи в репозиторий не добавляй.
5. Проведи проверки и эксперименты из условия. Запиши команды, наблюдения,
   причины ошибок и подтверждение исправления.
6. Предоставь результаты, перечисленные в задании, и подготовься объяснить
   решения своими словами. Затем переходи к следующему модулю.
7. Останови ненужный стенд; после облачной практики удали учебные ресурсы
   по инструкции и проверь, что оплачиваемые ресурсы не остались.

## Доступность стендов

Условия Linux-инцидентов сформулированы, но Ansible-плейбуки подготовки
неисправностей пока не реализованы. Для выполнения этих кейсов сначала
потребуется подготовленный стенд.

Наличие документов не означает, что каждый стенд проверен на твоей платформе.
Перед выполнением проверь доступность стартовых файлов и требования модуля.
Облачная практика платная; расчёт бюджета находится в условии модуля 08.

## Инициализация практики

Требуется Python 3. Из корня клонированного репозитория выполни:

```bash
bash tasks/init.sh 00
cd tasks/00/workspace
```

Для следующего задания замени номер: `bash tasks/init.sh 06`.
Команда копирует общие артефакты в `tasks/06/workspace`. Повторный запуск
не перезаписывает существующую практику. Рабочие каталоги исключены из Git курса;
для сдачи создай собственный Git-репозиторий внутри рабочего каталога.
Практики `02-extra` и `09` получают только условие: стенд готовится по заданию.
Общие исходники меняются в `artifacts/`, уже созданные рабочие копии не обновляются.

В корне курса: `README.md`, `tasks/` (условия и инициализация), `artifacts/`
(общие исходные материалы). Скрытые служебные файлы Git остаются на месте.
