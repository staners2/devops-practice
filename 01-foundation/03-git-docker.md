# День 3. Git и Docker: сохранить изменение и упаковать приложение

## Git: история работы

Git хранит версии файлов. Репозиторий содержит историю; commit фиксирует
выбранное состояние; ветка позволяет вести изменение отдельно; remote указывает
на удалённый репозиторий. GitLab и GitHub предоставляют хостинг, обсуждение
изменений и другие инструменты вокруг Git.

```text
Файл изменён → git add → staging → git commit → локальная история
Локальный commit → git push → удалённый репозиторий → Merge Request
```

`status` показывает состояние, `diff` — изменения, `add` выбирает содержимое
будущего коммита. Commit не отправляет ничего на сервер. MR/PR предлагает
объединить изменения и даёт команде место для review. `.gitignore` исключает
неотслеживаемые локальные файлы; секреты в историю добавлять нельзя.

## Docker: одинаковая упаковка приложения

Образ содержит подготовленные файлы и настройки запуска; контейнер — запущенный
экземпляр образа. Dockerfile описывает сборку, registry хранит образы, tag — имя
версии или другой изменяемый указатель на образ.

```dockerfile
FROM nginx:stable
COPY index.html /usr/share/nginx/html/index.html
```

Это пример упаковки страницы в образ nginx. `FROM` выбирает основу, `COPY`
добавляет файл. Сборка образа не означает запуск контейнера.

```text
Образ → контейнер, слушающий порт 80
Публикация 8080:80 → клиент обращается к localhost:8080
```

Порт слева относится к Docker-хосту, справа — к контейнеру. Инструкция `EXPOSE`
сама не публикует порт. Логи показывают сообщения основного процесса, а остановка
этого процесса обычно завершает контейнер.

## Самопроверка и ответы

1. Чем commit отличается от push?

   **Ответ:** commit записывает локальную версию, push передаёт коммиты удалённому репозиторию.

2. Чем образ отличается от контейнера?

   **Ответ:** образ — подготовленная основа, контейнер — её экземпляр с работающим процессом и собственным состоянием.

3. Почему изменение исходников не всегда меняет контейнер?

   **Ответ:** файлы могли быть скопированы в образ при прошлой сборке; нужны новая сборка и новый контейнер.

4. Зачем registry?

   **Ответ:** хранить и распространять образы между разработчиками, CI и окружениями.
