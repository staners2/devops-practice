# День 4. CI/CD: автоматизировать путь изменения

## Зачем это после Git и Docker

Изменение уже хранится в Git, приложение можно упаковать в образ. CI/CD запускает
согласованные проверки и операции доставки автоматически, чтобы команда не
повторяла их вручную для каждого изменения.

CI — регулярная интеграция изменений с автоматическими проверками. Continuous
delivery поддерживает готовность к выпуску, при этом выпуск может требовать
ручного решения. Continuous deployment автоматически выпускает прошедшие
проверки изменения.

## Основные слова

| Термин | Значение |
| --- | --- |
| Pipeline | Запуск набора связанных CI/CD-операций |
| Job | Одна операция: например, тест или сборка |
| Stage | Группа jobs в схеме pipeline |
| Runner | Исполнитель, на котором запускаются jobs |
| Artifact | Сохранённый результат job, например отчёт |
| Registry | Хранилище собранных образов |
| Deployment | Развёртывание выбранной версии в окружении |
| Rollback | Возврат к ранее принятой версии или конфигурации |

## Пример для чтения

```yaml
stages: [check]
check-page:
  stage: check
  script:
    - test -s index.html
```

Job проверяет, что файл страницы существует и не пуст. Он не собирает образ
и не развёртывает приложение. Runner должен иметь shell и команду `test`;
в реальных заданиях окружение исполнения заранее определено.

### Чекпоинт: что именно автоматизировано

Что эта job проверяет, а чего не проверяет? Можно ли по её успеху утверждать,
что сайт работает?

## Общая последовательность

Изменение → MR → проверки → сборка образа → публикация в registry → deployment
→ проверка приложения. Публикация образа и его запуск на сервере — разные этапы.

Настройки передают через переменные CI. Пароли и токены хранят в подходящем
механизме секретов, а не прямо в YAML. При падении job сначала читают её лог
и код завершения команды.

## Самопроверка и ответы

1. Чем job отличается от pipeline?

   **Ответ:** job — отдельная операция, pipeline — запуск связанного набора операций.

2. Кто выполняет команды?

   **Ответ:** runner в выбранном окружении исполнения.

3. Образ появился в registry. Обновилось ли приложение?

   **Ответ:** не обязательно; нужен deployment этой версии.

4. Как начать разбор неуспешного pipeline?

   **Ответ:** найти упавшую job и первую значимую ошибку в её логе.
