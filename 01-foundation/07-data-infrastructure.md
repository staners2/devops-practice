# День 7. Данные, события, инфраструктура и повторение

## Как технологии дополняют приложение

```text
Клиент → приложение → PostgreSQL: постоянные данные
                  → Redis: кеш и временные значения
                  → Kafka → обработчик: события для независимой обработки
Terraform → инфраструктурные ресурсы
Ansible → конфигурация серверов
Git и CI/CD → доставка изменений
Kubernetes → поддержание запущенных приложений
```

Это учебная схема. Каждое приложение не обязано использовать все перечисленные
технологии.

## PostgreSQL

Реляционная база хранит данные в таблицах. Строка — запись, столбец — поле,
ключ помогает идентифицировать и связывать записи. SQL используется для
запросов. Транзакция объединяет изменения, которые нужно завершить или отменить
вместе.

```sql
SELECT id, status FROM orders WHERE status = 'created';
```

Пример выбирает нужные поля заказов с указанным статусом, не изменяя их.
Писать запросы самостоятельно пока не требуется.

## Redis

Хранилище структур данных, часто используемое для кеша, сессий и счётчиков.
Ключ идентифицирует значение; TTL ограничивает время жизни. Промах кеша означает
отсутствие нужного значения — приложение должно знать, где получить исходные
данные. Сохранность после перезапуска зависит от persistence и конфигурации.

## Kafka

Producer публикует события в topic, consumer их читает. Partitions делят topic
на журналы; offset задаёт позицию в partition, consumer group объединяет
обработчиков. Прочтение не означает немедленное удаление сообщения. Событие
может обрабатываться повторно, поэтому важно понимать последствия повторения.

### Чекпоинт: разные задачи хранения

Почему базу заказов, кеш карточек и поток событий не следует считать
взаимозаменяемыми? Объясни возможное поведение приложения при отсутствии кеша.

## Terraform

Infrastructure as Code описывает ресурсы в конфигурации. Provider знает API
выбранной платформы; resource описывает объект; state связывает конфигурацию
с управляемыми объектами. Plan показывает предполагаемые изменения, apply
выполняет их. State может содержать секреты; его нельзя публиковать как обычный
учебный текст.

## Итоговая самопроверка

1. Где постоянно хранится заказ в учебной схеме?

   **Ответ:** в PostgreSQL; Redis в этой схеме служит кешем.

2. Чем событие Kafka отличается от HTTP-запроса к обработчику?

   **Ответ:** producer записывает событие в журнал, обработчик читает его независимо; прямой HTTP-вызов непосредственно обращается к сервису.

3. Создаст ли публикация образа в registry новую VM?

   **Ответ:** нет; публикация образа, создание инфраструктуры и deployment — разные операции.

4. Что в примере делает Terraform, а что Ansible?

   **Ответ:** Terraform управляет ресурсами инфраструктуры, Ansible — настройками серверов.

5. Расскажи весь путь изменения: от Git до HTTP-ответа пользователя.

   **Ориентир:** commit и MR → CI-проверки и сборка → registry → deployment → работа процесса → сетевой доступ и HTTP. Объясни роль Linux и зависимостей приложения.
