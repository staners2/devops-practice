# День 1. Linux: среда, в которой работает приложение

## Зачем это знать

Приложение работает как процесс операционной системы. Ему нужны файлы, права,
память и настройки. Linux управляет этими ресурсами; нужно понимать, какой
процесс работает, от чьего имени и где искать его сообщения.

## Основные слова

| Термин | Значение |
| --- | --- |
| Shell | Программа, которая читает команды и запускает их |
| Каталог и путь | Место хранения файлов и способ указать нужный файл |
| Пользователь и группа | Идентичности, через которые выдаётся доступ |
| Права rwx | Чтение, запись и выполнение; у каталога выполнение означает возможность войти в эту директорию через `cd` |
| Процесс, PID | Работающая программа и её идентификатор |
| Сервис | Приложение, которым управляет менеджер служб, часто systemd |
| Лог | Сообщения о событиях и ошибках приложения |
| Переменная окружения | Настройка, которую процесс получает при запуске |

`/etc` содержит системную конфигурацию, `/var` — изменяемые данные, `/home` —
домашние каталоги пользователей, `/tmp` — временные файлы. Абсолютный путь
начинается с `/`, относительный отсчитывается от рабочего каталога.

## Пример для чтения

```text
$ pwd
/home/student/orders
$ ls
app.py  requirements.txt  README.md
$ ps -o pid,user,args -p 2401
 PID USER    COMMAND
2401 student python app.py
```

Каталог проекта — `/home/student/orders`, приложение работает от пользователя
`student`. Наличие файла `app.py` не означает, что процесс запущен. `ps`
показывает процесс, но ещё не доказывает, что приложение отвечает клиентам.

### Чекпоинт: файл и процесс

Объясни разницу между файлом приложения, работающим процессом и его логом.
Назови, что из этого видно в примере.

## Назначение команд

- `pwd`, `ls`, `cd` — узнать и изменить рабочий каталог.
- `cat`, `tail` — прочитать файл или его последние строки.
- `ps`, `top` — посмотреть процессы.
- `chmod`, `chown` — изменить права и владельца.
- `systemctl status` — проверить состояние сервиса; `journalctl` — прочитать журнал.

Сервис может быть настроен на автозапуск и при этом сейчас не работать.
Перезапуск не объясняет причину ошибки: сначала смотрят состояние и журнал.
На этой неделе достаточно узнавать команды и объяснять их назначение.

## Самопроверка и ответы

1. Чем `app.py` отличается от процесса Python?

   **Ответ:** файл содержит программу; процесс — её выполняемый экземпляр.

2. Почему приложение может не прочитать существующий файл?

   **Ответ:** например, у пользователя процесса нет прав на файл или проход по каталогам.

3. Где искать сообщения сервиса?

   **Ответ:** в его логах; для сервиса systemd часто используют `journalctl -u` с именем сервиса.

4. Что даёт переменная окружения?

   **Ответ:** передаёт настройку процессу, например порт, без изменения его исходного кода.
