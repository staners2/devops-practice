# День 5. Ansible: описать состояние сервера

## Зачем это после CI/CD

Pipeline автоматизирует процесс доставки. Серверу также нужны пакеты, файлы
конфигурации и запущенные сервисы. Ansible описывает требуемое состояние
и приводит выбранные машины к нему, обычно подключаясь по SSH.

## Словарь

- **Inventory:** список машин и групп.
- **Playbook:** YAML с описанием работы на выбранных машинах.
- **Play:** применение набора задач к указанным hosts.
- **Task:** одно действие.
- **Module:** реализация действия, например управление пакетом или файлом.
- **Variable:** параметр, меняющий настройки без переписывания задач.
- **Become:** повышение привилегий для задачи, когда это необходимо.
- **Handler:** действие, уведомляемое изменившимися задачами, например reload сервиса.
- **Role:** способ организовать связанные задачи, шаблоны и параметры.

## Пример для чтения

```yaml
- name: Ensure nginx is installed
  hosts: web
  become: true
  tasks:
    - name: Install nginx package
      ansible.builtin.apt:
        name: nginx
        state: present
```

На машинах группы `web` требуется наличие пакета nginx. Пример предполагает
систему с apt. Если пакет уже установлен, задача обычно не меняет состояние.
Это пример идемпотентности: повторный запуск не должен выполнять лишние изменения.

### Чекпоинт: требование и команда

Сформулируй требуемый результат примера. Почему «nginx должен быть установлен»
отличается от безусловного повторения команды установки?

Ansible не делает любой shell-скрипт автоматически идемпотентным. Результат
зависит от модуля и описанного состояния. На первом уровне достаточно прочитать
такой playbook; писать его или готовить SSH-доступ пока не нужно.

## Самопроверка и ответы

1. Что определяет inventory?

   **Ответ:** какие машины и группы доступны для применения playbook.

2. Зачем `become`?

   **Ответ:** выполнить административное действие с повышенными привилегиями.

3. Зачем handler при изменении конфигурации?

   **Ответ:** выполнить связанное действие, например reload, когда конфигурация действительно изменилась.

4. Чем Ansible отличается от Terraform?

   **Ответ:** в нашем маршруте Ansible настраивает ОС и приложения, Terraform создаёт и изменяет инфраструктурные ресурсы; их возможности могут частично пересекаться.
