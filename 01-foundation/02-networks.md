# День 2. Сети: как клиент находит приложение

## Связь со вчерашней темой

Недостаточно запустить процесс: клиенту нужно знать адрес сервера и порт
приложения. При обращении по имени сначала нужно получить адрес через DNS.

## Основные слова

| Термин | Значение |
| --- | --- |
| IP | Адрес сетевого интерфейса или другой адресуемой точки в IP-сети |
| Порт | Число, помогающее направить трафик нужной службе на адресе |
| DNS | Система записей, в том числе сопоставляющих имена с IP |
| localhost | Имя локального компьютера в данном окружении |
| TCP | Транспорт с установлением соединения, упорядочиванием и повторной передачей данных |
| UDP | Передача отдельных датаграмм без этих гарантий TCP |
| HTTP | Протокол запросов и ответов приложения |
| HTTPS | HTTP с защитой TLS |

## Путь запроса

Для обычного HTTPS-запроса через TCP: имя → DNS → IP → TCP-соединение → TLS → HTTP.
Это упрощённая модель: HTTP/3 использует QUIC. На первом уровне детали протоколов
не требуются.

```text
Клиент запрашивает: https://orders.example/info
DNS возвращает:    192.0.2.20
Клиент соединяется с портом 443
Сервер возвращает: HTTP 200 и JSON
```

Имя помогает найти адрес. Порт 443 выбран по схеме HTTPS, если другой порт
не указан. Путь `/info` обрабатывает уже приложение.

### Чекпоинт: адрес и приложение

Объясни, за что отвечают DNS, IP, порт и путь. Может ли DNS работать, когда
само приложение остановлено?

## Чтение HTTP

```http
GET /health HTTP/1.1
Host: orders.example

HTTP/1.1 200 OK
Content-Type: application/json

{"status":"ok"}
```

Верхняя часть иллюстрирует запрос, нижняя — ответ. `GET` — метод, `/health` —
путь, `200` — статус, JSON — тело ответа. Группы кодов: 2xx — успех, 3xx —
перенаправления, 4xx — ошибки запроса или доступа, 5xx — ошибки сервера.

`curl` позволяет отправить запрос и увидеть ответ. Ошибка соединения возникает
раньше получения HTTP-ответа; HTTP 500 означает, что HTTP-ответ уже получен.

## Самопроверка и ответы

1. Чем IP отличается от порта?

   **Ответ:** IP адресует сетевую точку, порт помогает выбрать службу на ней.

2. Что означает `localhost` внутри контейнера?

   **Ответ:** локальное окружение этого контейнера; это не автоматически адрес хостовой ОС.

3. Почему HTTP 404 отличается от отказа соединения?

   **Ответ:** в первом случае приложение или промежуточный HTTP-сервер ответил; во втором HTTP-ответ не получен.

4. Зачем HTTPS?

   **Ответ:** TLS защищает передачу и позволяет проверять идентичность сервера по сертификату.
