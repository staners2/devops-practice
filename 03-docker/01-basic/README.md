# Docker: базовая практика

Уровень: **базовый**. Выполняется после изучения теории по теме.

## Требуется

Docker с Compose; свободный локальный порт.

## Инициализация

```bash
bash artifacts/init.sh 03 01
cd 03-docker/01-basic/workspace
```

Команду инициализации запускай из корня курса. Все дальнейшие команды — из рабочего каталога.

## Задание

1. Создай страницу index.html и Dockerfile на основе nginx, копирующий её в каталог сайта.
2. Собери образ с собственным tag и запусти контейнер с пробросом порта.

### Чекпоинт: первый контейнер запущен

- [ ] **Результат:** Образ собран с моим tag; контейнер запущен, публикация порта соответствует команде запуска.
- [ ] **Понимание:** Могу объяснить разницу образа и контейнера. Какой из двух портов в -p принадлежит хосту?

3. Проверь страницу через curl, посмотри ps, logs и содержимое контейнера через exec.

### Чекпоинт: приложение проверено

- [ ] **Результат:** curl показывает мою страницу; я нашёл контейнер через ps, прочитал logs и проверил файл через exec.
- [ ] **Понимание:** Могу объяснить, что проверяет каждая команда. Где буду искать причину, если контейнер есть, а страница недоступна?

4. Останови и удали контейнер; объясни, почему образ остался.
5. Опиши nginx в compose.yaml и подключи страницу через bind mount.
6. Пересоздай контейнер, проверь страницу и объясни отличие bind mount от named volume.

### Чекпоинт: Compose и данные

- [ ] **Результат:** После удаления контейнера образ остался; Compose запускает сайт, а пересоздание контейнера сохраняет подключённый файл страницы.
- [ ] **Понимание:** Могу объяснить EXPOSE, публикацию порта, bind mount и named volume. Изменится ли файл в образе от правки файла на хосте?

## Результат

Dockerfile, compose.yaml и результаты проверок. Объясни разницу EXPOSE и публикации порта.

Сохрани свои файлы в отдельном учебном Git-репозитории. Приложи наблюдения и объяснения, а не только команды.
